# test-vul 固件/系统漏洞复现仓库

本仓库仅保留内网授权测试环境中**已成功动态复现**的漏洞结果。

## 目录存放规则

```
<虚拟机名称>/                         # 一级目录：每台虚拟机一个
├── <漏洞名或CVE号>/                  # 二级目录：每个漏洞一个
│   ├── 复现情况.md                   # 复现文档（漏洞描述/影响版本/证据/结果/置信度）
│   └── poc.*                         # PoC 文件（脚本/命令/请求包）
└── <固件/镜像文件>                    # 若固件可在网络下载，放对应一级目录下
```

- 一级目录命名：使用台账中的虚拟机名称（文件系统安全，小写、空格转 `-`）；同一虚拟机的多个漏洞必须放在同一个一级目录下。
- 二级目录命名：`CVE 号` 或漏洞名（如 `CVE-2024-xxxx`、`system-path-command-injection`）。
- 每个二级目录必须包含 `复现情况.md`。

## 复现方式分层（如实标注）

每个漏洞的 `复现情况.md` 必须标注**复现方式分层**，禁止把「代码级确认」「SSH 辅助」当成「已复现」：

| 分层 | 含义 | 是否算「已复现」 |
|---|---|---|
| 真实网络攻击路径 | 从攻击机直接经 HTTP/网络协议触发漏洞端点 | ✅ |
| 认证后 Web 路径 | 先真实登录，再经 Web 配置/操作触发 | ✅ |
| SSH 辅助复现 | 端口不可达或需本机操作，SSH 进去触发 | ⚠️ 需标注端口可达性 |
| 代码级确认 | sink/版本比对确证，但未动态触发 | ❌ |

**关键原则**：按漏洞的真实利用方式复现，禁止用 root SSH 直接复刻 sink 冒充「漏洞复现」。

## 敏感信息

- `台账.md` 含内网 IP 与账号密码，已加入 `.gitignore`，**不入库**。
- 复现文档与 PoC 中不得出现真实密码、API 密钥或令牌；确需示例时使用占位符或环境变量。

## 复现与补充

- 复现需在**授权内网测试环境**内进行，禁止触碰外部/未授权系统。
- 复现完成后应清理目标机痕迹（见 workflow 的 finalize 清理步骤）。
- 版本比对须同时核查**基础版本 + 补丁状态 + 插件版本**，避免仅凭 `/etc/os-release` 误判。
