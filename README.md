# agent_security_dict

agent_security_dict 是面向**安全 Agent 漏洞发现、分析与验证能力**的评测数据集构建项目，整理漏洞样本、运行环境、复现步骤与证据，为可重复、可追溯的评测提供基准。

项目使用**基于 Codex 的自研多 Agent 编排漏洞挖掘工具**，通过多 Agent 协作开展候选分析、漏洞挖掘、验证与复核。样本基准由复现证据和复核结论确定，每轮评测对照基准记录检出、遗漏、误报、验证结果及报告质量。

当前样本覆盖 Web 服务、系统组件与固件场景，重点记录实际部署版本、认证与权限前提、配置条件和动态复现证据。

## 数据集构建

1. **收集候选**  
   结合 [历史漏洞台账.md](历史漏洞台账.md)、项目源码和公开漏洞资料，确定目标环境、受影响组件、漏洞类型与候选触发路径。

2. **核对环境**  
   记录实际部署版本、补丁状态、插件或组件版本，以及认证、权限、配置和网络可达性。保留台账信息与实测结果之间的差异。

3. **分析与复核**  
   使用自研编排工具分析漏洞根因、输入到敏感操作的数据流和利用路径，核对候选结论，整理待动态验证的问题。

4. **动态验证**  
   在对应测试环境中按实际入口触发问题，保存请求与响应、日志、执行结果等证据，并记录非默认配置、环境准备操作和辅助验证方式。

5. **整理基准**  
   为样本保存 `复现情况.md` 和 PoC，明确预期行为、实际结果、影响边界、验证方式与置信度。经复核成立且已动态验证的样本进入已验证样本集，其余候选单独跟踪。

## 评测流程

1. **定义任务与输入**  
   选定样本、评测目标和任务约束。漏洞发现任务提供目标源码或环境，基准报告与现成 PoC 留作评分参考；漏洞复现任务按约定提供漏洞信息或 PoC。两类任务分别统计。

2. **固定评测条件**  
   记录目标版本、部署配置、初始状态、可用权限，以及编排工具版本、工作流配置、模型、提示词和轮次或时间预算，便于对比不同轮次的结果。

3. **执行任务并留存记录**  
   运行自研编排工具，组织各 Agent 完成分析、验证与复核，保存原始输出、执行日志、候选漏洞和最终结论。

4. **对照基准判定**  
   检查是否正确识别漏洞、说明必要前提并完成约定验证。按根因和利用路径匹配基准，同一根因的重复报告先去重，额外发现经复核后单独记录。

5. **汇总结果**  
   分别记录成功、失败、遗漏、误报、环境受阻和待复核项，说明判定依据，并披露本轮纳入、完成与排除的样本。

### 评测指标

| 指标 | 统计口径 |
| --- | --- |
| 基准漏洞检出率 | 正确检出的基准漏洞数 / 本轮漏洞发现评测的有效基准漏洞数。 |
| 报告查准率（Precision） | 经复核成立的独立漏洞报告数 / 已完成复核的独立漏洞报告数；另列待复核数量。 |
| 动态验证成功率 | 按约定利用路径成功复现的基准样本数 / 本轮动态验证任务的有效基准样本数。 |
| 分析与报告质量 | 核对根因定位、认证与权限前提、影响边界、证据完整性和复现步骤。 |
| 执行开销 | 记录耗时、执行轮次，以及可取得的模型调用次数或 token 消耗。 |

分母为零时标记为“不适用”。环境受阻和排除项需说明原因；误报率（FPR）仅在具备经确认的阴性对照样本时计算。

## 目录组织

样本按“环境名称 / 漏洞名或 CVE”组织：

| 路径 | 内容 |
| --- | --- |
| `<环境名称>/<漏洞标识>/复现情况.md` | 目标信息、影响版本、触发前提、复现步骤、证据、结论与置信度。 |
| `<环境名称>/<漏洞标识>/<PoC 文件>` | 单文件 PoC、命令或请求示例。 |
| `<环境名称>/<漏洞标识>/poc/` | 由多个文件组成或带独立说明的 PoC 材料。 |
| [历史漏洞台账.md](历史漏洞台账.md) | 历史漏洞线索、目标信息和核对记录。 |

一级目录沿用台账中的虚拟机或环境名称，使用小写并将空格替换为 `-`；同一环境的多个漏洞放在同一目录。二级目录使用 CVE 号或描述性漏洞名，如 `system-path-command-injection`。

每个样本的 `复现情况.md` 应区分候选状态、已有复现记录与本轮评测结果，并记录镜像或固件来源、版本及必要配置。

## 复现路径与证据判定

| 路径或方式 | 记录要求 |
| --- | --- |
| 网络触发 | 记录经 HTTP 或其他协议访问实际漏洞入口的过程、可达性与触发证据。 |
| 认证后 Web 触发 | 记录真实登录过程、账号角色、所需权限，以及后续配置或操作。 |
| SSH 辅助 | 说明 SSH 用于环境准备、本机触发还是结果读取，并分别记录实际漏洞入口与辅助操作。 |
| 代码级确认 | 保存代码、版本或补丁依据；尚未动态触发时，动态验证状态保留为待验证。 |

网络任务的验证成功需有实际入口到目标行为的完整证据。在目标机上以 root 直接调用敏感函数，应记录为本机辅助实验；SSH 仅用于读取结果时，也应与网络触发步骤分别记录。

## 环境与记录维护

- 在授权测试环境中开展复现与评测，记录目标范围和必要的环境准备操作。
- 含环境地址与凭据的本地 `台账.md` 已加入 `.gitignore`，保持不入库。
- 文档、评测记录与 PoC 使用占位符或环境变量引用凭据，提交前检查真实密码、API 密钥和令牌。
- 测试结束后保留必要证据，移除测试文件并恢复临时配置，便于后续复测。
